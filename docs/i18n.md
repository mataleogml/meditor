# i18n

i18n is one optional config block. Omit it entirely and every locale-taking
function/prop defaults away — single-locale behavior is byte-identical to a
build with no i18n support at all.

## `I18nConfig`

```ts
// from "meditor" or the edge-safe "meditor/i18n" subpath
export interface I18nConfig {
  locales: string[];
  defaultLocale: string;
  routing: "prefix-except-default" | "prefix-all";
  messages?: Record<string, Partial<Messages>>; // editor-UI string overrides, per UI locale
}
```

Build one with `resolveI18n` (validates + fills defaults; throws if
`defaultLocale` isn't in `locales`):

```ts
import { resolveI18n } from "meditor/i18n";

export const i18n = resolveI18n({
  locales: ["en", "es"],
  defaultLocale: "en",
  routing: "prefix-except-default",
});
```

Pass the same object to `CmsConfig.i18n`, `createMarkdownAdapter({ locales,
defaultLocale, ... })`, and (if you use the SEO module) `buildMetadata`/
`buildSitemap`'s `i18n` option — one source of truth shared by the adapter,
the store, the editor, and public rendering.

`meditor/i18n` has **no Node imports** (no `fs`, no `next/server`) — safe to
import from an edge `proxy.ts`/middleware or any client bundle, unlike the
main `meditor` entry (which pulls in the filesystem adapter) or
`meditor/editor` (client components).

## Routing presets

- **`prefix-except-default`**: the default locale is unprefixed (`/about`);
  every other locale is prefixed (`/es/about`). Preserves an existing
  single-locale site's URLs verbatim — zero SEO migration when adding a
  second locale later.
- **`prefix-all`**: every locale is prefixed, including the default
  (`/en/about`, `/es/about`).

Helpers, all pure functions of `(i18n, ...)`:

```ts
import { localizedPath, localizedHref, routeLocale } from "meditor/i18n";

localizedPath(i18n, "/about", "es");   // "/es/about"
localizedPath(i18n, "/about", "en");   // "/about"  (prefix-except-default, en is default)
localizedHref(i18n, "#anchor", "es");  // "#anchor" (anchors/external/mailto/tel pass through)

routeLocale(i18n, "/en/about");
// prefix-except-default -> { type: "redirect", pathname: "/about" }
//   (canonicalizes an explicit default-locale prefix — kills duplicate content)
routeLocale(i18n, "/about");
// prefix-all -> { type: "rewrite", pathname: "/en/about" }
```

Wire `routeLocale` into your edge proxy/middleware to canonicalize or
rewrite bare paths per the preset — `routeLocale`'s verdict maps directly
onto `NextResponse.redirect`/`.rewrite`/`.next()`. It never invents a
verdict that can't exist for the chosen preset.

## Content layout on disk

`createMarkdownAdapter` mirrors the routing preset's "default is special"
shape on the filesystem, regardless of which preset you actually route
with: the **default locale lives flat** at `contentDir` (so adding i18n to
an existing single-locale site moves zero files), and every other locale
lives under `contentDir/<locale>/`:

```
content/
  home.md         # default locale (en)
  about.md
  .drafts/
    about.md      # default-locale draft
  es/
    home.md        # es translation
    .drafts/
      about.md     # es draft
```

`ContentAdapter.locales` is also the **traversal guard** for the locale path
segment — any locale not in that allowlist throws before it reaches `fs`.

## Fallback

`ContentStore.getPublished(slug, locale)` merges the requested locale over
the default-locale base via `mergeLocalized`:  `meta` merges field-by-field
(a translation can override just `title` and inherit the rest), `slices`
replaces wholesale if the locale file has any (never a partial/positional
merge — that's a footgun), `body` falls back if empty. The returned
`LocalizedPage.isFallback` is `true` when the locale has no file at all and
the default locale's content served in its place — `EditorShell` shows a
dismissible "not yet translated" banner off this flag.

## The editor's locale switcher

`EditorShell`/`SiteEditor` render a `<select>` when `locales.length > 1`.
Picking an already-translated locale just navigates with `?locale=` set;
picking an untranslated one first calls `actions.createTranslation(slug,
toLocale)` — which seeds a **draft** (never published) copy of the default
locale's current published content — then navigates. `translatedLocales`
(locales where the page already has published content or a draft) is what
decides which behavior fires; compute it from `adapter.exists`/`hasDraft`
per locale (see the reference host's `app/editor/[slug]/page.tsx`).

## Editor UI strings

Independent axis from content locale: `CmsIntlProvider`/`useT` translate the
editor's own chrome (button labels, confirm dialogs), not your content. See
[editor.md](./editor.md#cmsintlprovider--uset).

```tsx
<CmsIntlProvider messages={i18n.messages?.[uiLocale]}>
  {children}
</CmsIntlProvider>
```

`messages` is deep-merged onto the package's English defaults
(`ui/messages.ts`'s `defaultMessages`) — override only the keys you need.
An English-speaking editor can perfectly well edit `es` content; the two
locales never have to match.
